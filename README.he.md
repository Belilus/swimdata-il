## לראות הכול בפקודה אחת

מריצים `bash build.sh` (תלויות: `pip install -r requirements.txt`) ובונים את **`web/dashboard.html`** מתוך קובצי ה־PDF, ואז פותחים בדפדפן — קובץ אחד עצמאי: טבלאות מדליות, פודיומים, תיקי שחיינים דו־לשוניים, לוח שיאים, ופאנל חי של אתגר הנתונים. מערך הנתונים והדשבורד **לא נשמרים בגיט** — ראו [נתונים ופרטיות](#נתונים-ופרטיות).

## מה זה

איגוד השחייה מפרסם תוצאות **רק כ־PDF** (דרך `loglig.com`). הפרויקט מפרסר את ה־PDF לפי *גיאומטריה* (קואורדינטות של מילים → עמודות, לא לפי סדר טקסט שביר), מנרמל ל־**BCNF**, פותר זהויות דו־לשוניות מבולגנות, וטוען מסד שאפשר לשאול. יש בו **שתי אליפויות אמיתיות**:

|  | תחרות 1 (גילאים צעירים, שני מקורות) | תחרות 2 (חורף נוער ובוגרים, loglig) | סה״כ |
|--|--|--|--|
| שחיות | 1,701 | 3,069 | **4,770** |
| שחיינים | 496 | 815 | **1,311** |
| מועדונים | 39 | +33 | **72** |
| משחים | 74 | 266 | **340** |

**אפס מפתחות זרים יתומים.** הדוח המלא: **[`report/report.he.md`](report/report.he.md)** (עד 5 עמודים, התוצר המדורג). PDF: [`report/report.he.pdf`](report/report.he.pdf).

## אתגר ניהול הנתונים (הכותרת)

**פתרון ישויות דו־לשוני.** אותו מועדון מאוית בארבע צורות (*Macabbi / Maccabi / Maccabbi / Macabi*), בשתי שפות ושני כתבים, בשני מקורות ושתי תחרויות. המפתח הוא **קוד האיגוד המספרי**, והשם הקנוני נבחר לפי השכיח ביותר — וכך **72 איות מתכווצים ל־39 מועדונים**, עם שובל ביקורת. רשימת הזינוק בעברית מחוברת לגיליון התוצאות באנגלית דרך הזוג המשותף `(משחה, מקצה, מסלול)` בהתאמה דטרמיניסטית של **98.3%**. ראו את הפאנל החי בדשבורד ואת `docs/schema-design.md`.

## איך מריצים (פקודה אחת)

```bash
python3 -m pip install -r requirements.txt
bash build.sh                # מפרסר שתי תחרויות → מסד מנורמל → דשבורד וייצוא
python3 src/app.py           # אופציונלי: אפליקציית שאילתות במסוף
```

ה־SQL הקנוני מיועד ל־**PostgreSQL** (`sql/01_schema.sql`); הראנר מריץ את אותו SQL על **DuckDB** משובץ, בלי להתקין שרת.

## מקור הנתונים והיקף

תוצאות ציבוריות של האיגוד (`isr.org.il/Competitions.ASP` → `loglig.com`). המאגר **עצמאי**. הוא גם מתעד איך אותו מודל מתחבר לפלטפורמת שחייה שהמחבר בונה (`docs/swimedge-sync.md`) — יישום אמיתי, ברמת תכנון בלבד.

## נתונים ופרטיות

הנתונים מתפרסמים בציבור, אבל מזהים שחיינים — **כולל קטינים**. לכן קובצי ה־PDF של התחרויות וכל תוצר ברמת שחיין **לא נכנסים לגיט**:

- **לא בגיט:** `web/data.js`, `web/dashboard.html`, `web/swimedge_bundle.json`, `docs/sample-query-output.txt`, `data/`, וקובצי התחרות ב־`samples/` (`results_*`, `startlist_*`);
- **כן בגיט:** כל הקוד, הסכימה וה־SQL, הדוחות, ו־PDF תקנון אחד (כללים בלבד, בלי נתונים אישיים).

הכול נבנה מחדש מקומית: שמים את קובצי ה־PDF הציבוריים ב־`samples/` ומריצים `./build.sh`.
